# Vector database – a database of embeddings

# SiT SINGAPORE INSTITUTE OF TECHNOLOGY

Vector DBs complement traditional DBs, they don't replace them. Most production systems use both.

| Problem               | Example                                   |                                           | Impact                                          |
| --------------------- | ----------------------------------------- | ----------------------------------------- | ----------------------------------------------- |
| Feature               | Traditional DB (SQL)                      | NoSQL DB                                  | Vector Database                                 |
| Knowledge cutoff      | "Who won the 2025 Super Bowl?" → wrong or | Cannot answer questions about             | High-dimensional vectors + metadata information |
| Data type             | Rows, columns, text, numbers              | Documents, key-value, graphs, wide-column |                                                 |
| Hallucination         | title/DOI                                 |                                           |                                                 |
| Query type            | SELECT \* WHERE name = 'Alice'            | db.find({ name: 'Alice' })                | "Find 10 nearest vectors to this query vector"  |
| Index type            | generic answer                            | Hash, LSM-tree, inverted B-tree, hash     | HNSW, IVF, PQ                                   |
| No source attribution | diverse data                              | index                                     | Users cannot verify answers                     |
| Use case              | Structured data lookup                    | Flexible schema, high-write workloads     | Semantic similarity search retraining           |
| Example               | PostgreSQL, MySQL                         | MongoDB, Redis, Cassandra                 | Pinecone, Weaviate, Qdrant, Chroma              |

# Limitations of pure vector search

# SINGAPORE INSTITUTE OF TECHNOLOGY

| Limitation              | Example                                                               | Why It Happens                                  | Solution                              |
| ----------------------- | --------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------- |
| Keyword blindness       | Query: "error code E-4012" — vector search misses exact match         | Embeddings capture meaning, not exact strings   | Hybrid search (BM25 + dense)          |
| Knowledge cutoff        | refuses recent events                                                 |                                                 |                                       |
| Acronym/jargon mismatch | Query: "CSAT scores" — retrieves "customer satisfaction" tangentially | Acronyms may not embed well                     | Domain-specific embedding fine-tuning |
| Global/thematic queries | "What are the main themes across all documents?"                      | No single chunk contains the answer             | GraphRAG or community tasks summaries |
| Multi-hop reasoning     | "How does Policy A affect Outcome B?"                                 | Requires connecting info across multiple chunks | Knowledge graphs / Agentic RAG        |
| Recency bias            | Retrieves old docs that are semantically closer                       | No built-in recency awareness                   | Metadata filtering by date retraining |

| Type                               | How It Works                                               | Speed / Accuracy                 | Best For                                                                |
| ---------------------------------- | ---------------------------------------------------------- | -------------------------------- | ----------------------------------------------------------------------- |
| Domain                             | Stronger embedding model rescores candidates               | Fast / Good                      | Lightweight reranking without cross-encoder cost                        |
| Bi-encoder Refinement              | Microsoft Copilot, Glean                                   |                                  | Searches internal docs, emails, Slack                                   |
| Cross-encoder Neural               | Jointly encodes \[query + passage] → relevance score       | Slower / Highest                 | Default production RAG: BGE-Reranker, Cohere                            |

# Query transformation - Improving Retrieval by Rewriting the Query

# SiT SINGAPORE INSTITUTE OF TECHNOLOGY

| Technique                               | How It Works                                            | Example                                                                                   | Key Decisions                                      |
| --------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------- |
| HyDE (Hypothetical Document Embeddings) | Convert user question to a vector                       | Query: "What causes aurora?" → LLM generates a hypothetical answer, embed that instead    | Retrieve top-K most similar chunks                 |
| Multi-query retrieval                   | LLM generates multiple query variants, retrieve for all | "RAG search?" → also searches "how to measure RAG quality", "RAGAS metrics"               | Often the high-value improvement for minimal cost. |
| Step-back prompting                     | Ask a broader question first                            | "Why did the 2008 crash happen?" → first retrieve "causes of financial crises" to answer. | Context: {chunks}                                  |
| Sub-question decomposition              | Break complex question into parts                       | "Compare RAG and fine-tuning" → sub-Q1: "What is RAG?" sub-Q2: "What is fine-tuning?"     | Generate which LLM? Temperature? Max tokens?       |
| (Optional) Cite                         | Attach source references to answer                      | How to format citations?                                                                  |                                                    |

# RAG evaluation - If you can’t measure it, you can’t improve it

# SiT SINGAPORE INSTITUTE OF TECHNOLOGY

| Metric             | What It Measures                  | Formula/Method                        | Good Score |
| ------------------ | --------------------------------- | ------------------------------------- | ---------- |
| Context Precision  | Are retrieved docs relevant?      | Relevant retrieved / Total retrieved  | > 0.8      |
| Context Recall     | Did we find all relevant info?    | Relevant retrieved / All relevant     | > 0.9      |
| Faithfulness       | Is answer grounded in context?    | LLM checks each claim against context | > 0.9      |
| Answer Relevancy   | Does answer address the question? | Cosine sim(question, answer)          | > 0.85     |
| Answer Correctness | Is the answer factually correct?  | Compare to ground truth               | > 0.8      |
| RAGAS Score        | Combined evaluation               | Harmonic mean of above metrics        | > 0.85     |

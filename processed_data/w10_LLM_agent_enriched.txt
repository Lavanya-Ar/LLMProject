Levels of Agency: How Much Control Does the LLM Have?

# SINGAPORE INSTITUTE OF TECHNOLOGY

| Agency Level Description                                | How that's called | Example Pattern                                      |
| ------------------------------------------------------- | ----------------- | ---------------------------------------------------- |
| LLM output has no impact on program flow                | Simple processor  | process\_llm\_output(llm\_response)                  |
| LLM output determines basic control flow                | Router            | if llm\_decision(): path\_a() else: path\_b()        |
| LLM output determines function execution                | Tool call         | run\_function(llm\_chosen\_tool, llm\_chosen\_args)  |
| LLM output controls iteration and program continuation  | Multi-step Agent  | while llm\_should\_continue(): execute\_next\_step() |
| One agentic workflow can start another agentic workflow | Multi-Agent       | if llm\_trigger(): execute\_agent()                  |

# LLM as the ‘brain’

# SINGAPORE INSTITUTE OF TECHNOLOGY

The LLM is the central controller that perceives, reasons, decides, and orchestrates everything else

| Role           | What It Does                                                                             | Example                                                                              |
| -------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Perceiver      | Reads and interprets user input, tool outputs, and environment signals                   | User says "What's the weather in Paris?" → LLM understands this requires a tool call |
| Reasoner       | Thinks step-by-step about what to do next (chain-of-thought)                             | "I need to call the weather API. Let me format the city parameter as 'Paris, FR'"    |
| Decision Maker | Chooses which action to take: call a tool, ask for clarification, or give a final answer | Decides to call get\_weather(city="Paris") instead of guessing                       |
| Orchestrator   | Coordinates memory retrieval, tool execution, and response generation in the right order | Retrieves user's preference for Celsius from memory → calls API → formats response   |

# Memory: How Agents Remember

| Type of Memory              | Description                            | Storage                                     | Example                                   |
| --------------------------- | -------------------------------------- | ------------------------------------------- | ----------------------------------------- |
| Short-Term (Working Memory) | current context in the prompt          | Stored in context window                    | User just asked about Python              |
| Semantic Memory             | Facts & knowledge                      | Stored in Pinecone, Chroma, FAISS, Weaviate | Company policy says refunds take 5-7 days |
| Episodic Memory             | Past experiences & interaction history | Stored in Database logs, Json files         | Last Tuesday, this tool failed            |

# Key Insight

Semantic = "What do I KNOW?" → Facts, documents, policies

Episodic = "What have I DONE?" → Past attempts, tool failures, user preferences

Without Episodic Memory, an agent repeats the same mistakes.

Without Semantic Memory, it guesses.

# Other reasoning paradigms

# SiT SINGAPORE INSTITUTE OF TECHNOLOGY

| Paradigm            | Feature                                                       | How It Works                                                                                           | Best For                                                                 | Limitation                                                          |
| ------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Traditional Chatbot | Al Agent                                                      | Think → Act → Observe → Repeat                                                                         | General-purpose tasks, QA with tool use, fact-checking                   | Can get stuck in loops; no global plan                              |
| Plan-and-Execute    | Autonomy                                                      | First creates a complete plan (list of steps), then executes each step sequentially. Revised if fails. | Complex multi-step tasks, research workflows, report generation          | Upfront plan may be wrong; replanning is costly                     |
| Tools               | Plan all steps → Execute step 1 → Execute step 2 → ... → Done |                                                                                                        |                                                                          |                                                                     |
| Reflexion           |                                                               | Attempt → Evaluate → Reflect → Retry (with reflection in memory)                                       | Code generation, tasks with clear success/fail criteria                  | Requires clear evaluation criteria; multiple attempts are expensive |
| Goal Completion     | Tree-of-Thought (ToT)                                         | Generate multiple paths → Evaluate each → Prune bad paths → Expand best path                           | Puzzles, math, creative writing, problems with multiple valid approaches | Very expensive (many LLM calls); overkill for simple tasks          |
| Language Agent      | Tree Search (LATS)                                            | Expand → Simulate → Evaluate → Backpropagate → Select                                                  | Decision-making under uncertainty, game-like environments                | High computational cost; complex to implement                       |

# Summary &#x26; key takeaways

# SIT Internal

# SiT SINGAPORE INSTITUTE OF TECHNOLOGY

# Agents Agency

An agent is an LLM that can perceive, reason, act, and learn — not just generate text.

# Four components

Every agent has an LLM (brain), Memory (context), Tools (capabilities), and Planning (strategy).

Simple process: process_llm_output(llm_response)

Impact on program flow: if llm_decision(): path_a() else: path_b()

# ReAct is the default

Think → Act → Observe → Repeat is the most common reasoning paradigm; learn it first, then explore others.

# Architecture matters

Choose the right pattern: single agent for simple tasks, multi-agent for complex workflows, human-in-the-loop for high-stakes decisions.

LLM output determines function execution: run_function(llm_chosen_tool, llm_chosen_args)

# Frameworks accelerate you

Don't build from scratch — LangChain, CrewAI, AutoGen, and smolagents handle the plumbing so you can focus on logic while llm_should_continue():

# Safety is non-negotiable

Agents can ACT — scope permissions, sandbox execution, add guardrails, log everything, and keep humans in the loop.

# Start simple, iterate

Begin with one tool and one LLM call. Get that working. Then add memory, then multi-step reasoning, then multi-agent.

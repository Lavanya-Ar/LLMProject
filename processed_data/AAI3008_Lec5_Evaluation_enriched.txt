# F1 Score Calculation

F1 is computed based on word overlap between the predicted answer and the gold (correct) answer.

# Formula for F1 Score

F1 = 2 × Precision × Recall / Precision + Recall

# Where:

- Precision = (Number of overlapping words) / (Total words in the predicted answer)
- Recall = (Number of overlapping words) / (Total words in the ground-truth answer)

Source: https://nlp.cs.washington.edu/triviaqa/

# Token Embedding

- Compute a BERT embedding for each token *xi and xj*.

# Aggregation

- Scores for all token pairs are aggregated to compute precision, recall, and F1-score.
- Precision: How well candidate tokens match reference tokens.
- Recall: How well reference tokens are covered by candidate tokens.
- F1-score: Harmonic mean of precision and recall (main evaluation score).

# Formulas

- *RBERT = (1/∑j T<xj, PBERT) + (1/∑j xj)</x*
- *FBERT = 2PBERT · RBERT / (PBERT + RBERT)*

# Beam Search

SIT Internal

Instead of choosing the best token to generate at each timestep, we keep 𝑘 possible tokens at each step.

- BOS arrived the green aardvark
- BOS arrived the witch zebra

This fixed-size beam width memory footprint 𝒌 is called the beam width.

# Figure 13.8

Beam search decoding with a beam width of k = 2. At each time step, we choose the k best hypotheses, form the V possible extensions of each, score those k × V hypotheses and choose the best k = 2 to continue. At time 1, the frontier has the best 2 options from the initial decoder state: arrived and the. We extend each, compute the probability of all the hypotheses so far (arrived the, arrived aardvark, the green, the witch) and again chose the best 2 (the green and the witch) to be the search frontier. The images on the arcs schematically represent the decoders that must be run at each step to score the next words (for simplicity not depicting cross-attention).

- The higher the probability, the lower the perplexity.
- The smaller the probability, the more confused the model is.
- Lower perplexity means the model is more confident in its predictions, while higher perplexity suggests it is more uncertain.
- If a model is perfectly predicting the test data (assigns probability 1 to the correct words), its perplexity is 1.

# Perplexity

A perplexity (PPL) of 1.92 is extremely low.

Often considered near-human-level performance for token-level language modelling.

Perplexity measures model confidence, and achieving very high confidence on real language is itself very hard.

# Why In-context learning works

# SINGAPORE INSTITUTE OF TECHNOLOGY

Concept: a latent variable that contains various document-level statistics. LM uses the in-context learning prompt to “locate” a previously learned concept.

1. Pretraining documents are conditioned on a latent concept (e.g., biographical text)

Imagine the model’s brain has a giant "switchboard."

- In a Few-Shot scenario, your examples help the model flip the right switches.
- In a Zero-Shot scenario, the instruction itself is powerful enough to flip the switch.
2. Create independent examples from a shared concept. If we focus on full names, wiki bios tend to relate them to nationalities.
3. Concatenate examples into a prompt and predict next word(s). Language model (LM) implicitly infers the shared concept across examples despite the unnatural concatenation.

# SINGAPORE INSTITUTE OF TECHNOLOGY

1. Generate an initial response to the prompt
2. Based on the original prompt and output, the model is prompted again to scale generate multiple questions that verify and analyze the original answers.
3. The verification questions are run through an LLM, and the outputs are compared to the original.
4. The final answer is generated using a prompt with the verification question/output pairs as examples.

# Fine Tuning / Alignment

- Temperature: Related to the diversity of the output, higher temperature for better diversity
- Max tokens: The max length of the generated token sequence. (Eg, One token ~ 4 characters)
- Stop sequences: make the model stop generating tokens at a desired point
- Top-p: Consider only top tokens whose likelihood add up to P
- Frequency penalty: discourage the model from repeating the same words or phrases
- Presence penalty: encourage the model to include a diverse range of tokens

Biases in LLM-as-Judge
SiT SINGAPORE
INSTITUTE OF TECHNOLOGY

# Position Bias

- When comparing A vs B, model tends to prefer whichever is shown FIRST (or sometimes LAST)
- Fix: Swap order and average

# Verbosity Bias

- Model tends to prefer LONGER responses (even if shorter one is more accurate)
- Fix: Explicitly instruct "length ≠ quality"

# Self-enhancement Bias

- GPT-4 as judge tends to prefer GPT-4's outputs
- Fix: Use different model as judge

# Style over substance

The model has no way to know what your company means by "Code Red/Blue/Yellow."

- Prefers well-formatted, confident text even if factually wrong
- Fix: Grade criteria separately

LLM quality is multi-dimensional. Always use multiple evaluation approaches together.

Expensive and slow, but irreplaceable for subjective quality assessment.

Fast + semantic understanding. But beware of systematic biases (position, verbosity, self-enhancement).
